# Эксперимент № 012 — 2026-11-26

## Этап 3: иерархия — «спуск по таксономии» + entailment (фаза 2)

**Статус:** **пред-регистрация.** Код не писался; прогон — только после утверждения протокола.
**Место:** минимальный жизнеспособный путь **1 → 3** (`PROGRAM.md` §6). Первый этап с внешним
эталоном и без проблемы «полноты признаков».
**Вопрос:** восстанавливает ли модель таксономическую структуру — т.е. при подстановке понятия
в общий шаблон ответ **спускается на уровень ниже в правильную ветку**, а не остаётся тем же и
не уходит к предку/в чужую ветку?

> **Ключевое ограничение (из 009/011).** Свободный top-k первого токена мерит **синтаксис**
> (`a/an/the/being/having`; top-10 почти инвариантен по слову). поэтому:
> (i) читаем только **ограниченный candidate-set**, не свободный top-k;
> (ii) шаблон обязан быть **level-invariant по считыванию** (`Q`) и при этом
> **content-tracking** (`MI`) — иначе «спуск» неотличим от синтаксической массы;
> (iii) любой эффект проходит **frame-robustness** и **nonce-контроль**.

---

## 1. Что тестируем (одно утверждение → два канала)

**Ядро:** поведение модели должно двигаться по иерархии вниз при движении понятия вниз.

- **Канал G (генерация, «спуск»).** Шаблон запрашивает членов/подтипы понятия `C`;
  ответ должен лежать **в поддереве `C`** и на **уровень ниже** `C`.
- **Канал E (entailment, `X is a Y`).** `P(Yes)` выше для верных пар `X⊂Y` и падает с
  таксономической дистанцией.

Оба канала — чтение распределения по **токенам-кандидатам** (единственная надёжная метрика).
RDM/Mantel **не используется** как основной тест (RDM производна и readout-специфична, 004);
допускается лишь как вторичная диагностика и в вердикт не входит.

---

## 2. Гипотезы и пороги (пред-регистрация)

Уровень ответа считаем «глубиной» `d(·)` (super → d=0, basic → d=1, sub → d=2 для триад;
для руки (b) — кратчайшее гипонимическое расстояние от корня фрагмента).

- **G-valid (поддерево).** Для шаблона `T` и понятия `C` доля массы на **истинных потомках**
  `C` (candidate-set) `AUC(потомок vs не-потомок) ≥ 0.80`, и **margin** над частотным baseline
  `≥ 0.05`. Требуется на **≥2 шаблонах** и **≥2 моделях/условиях**.
- **G-step (шаг вниз).** Медианный `d(ответ) − d(C) = +1` (допуск: медиана в `[0.7, 1.3]`),
  и **монотонность**: `Spearman(d(C), d(ответ)) ≥ 0.5` по всем понятиям набора, `p < 0.01`
  (перестановки 1000). Требуется на **≥2 шаблонах**.
- **E-entail.** `AUC(верные is-a / неверные) ≥ 0.80`; `P(Yes)` убывает с дистанцией
  (`Spearman ≤ −0.3`, `p < 0.01`); margin над lexical+length baseline `≥ 0.05`.
- **Общий вердикт.** `иерархия подтверждена` = (G-valid ∧ G-step на ≥2 шаблонах) **и**
  (E-entail). `readout-local` — если только один канал G/E. `absent` — иначе.
  Отрицательный результат фиксируется как результат (цель задана внешне — WordNet/триады).

## 4. Candidate-set и факторный контроль

Не читаем свободный top-k. Для понятия `C` строим **сбалансированный** набор кандидатов из
таксономии, каждое слово помечено:

| метка | что значит | роль |
|---|---|---|
| `desc` | истинный потомок `C` | цель |
| `anc` | предок `C` | ловушка «вверх» |
| `sib_branch` | тот же уровень, **чужая ветка** | контроль «не просто частое» |
| `right_branch_wrong_level` | ветка `C`, неверный уровень (предок/слишком глубоко) | контроль level-step |
| `unrelated` | вне таксономии | фон |

Кандидаты в слотах-шаблонах суть **слова этих классов**; метрики считаются по массе на классах.
Дефолт: `K = 50` кандидатов на понятие (≥6 потомков, остальные — стратифицированы по классам).

## 5. Шаблоны и их калибровка (этап 3.0, до основного прогона)

**Принцип:** шаблон «общий, без концепт-якорей» = **level-invariant по `Q` + content-tracking `MI`**.

- **Концепт-якорь** (контаминант): слово шаблона, лексически/семантически связанное с понятием
  набора. Проверка — пересечение лексики + близость по со-встречаемости/эмбеддингам; при
  попадании шаблон отбраковывается.
- **Реляционный якорь** (`kind of`, `include`, `is a`) — допустим, но его вклад измеряется.

**Кандидаты (дефолт, дегустация; финал — по калибровке):**
- канал G: `Examples of {X} include`, `Types of {X} include`, `{X}, such as`, `A {X} can be a`,
  `Some {X} are`, `{X} include`;
- канал E: `{X} is a {Y}.`, `Every {X} is a {Y}.`, `A {X} is a kind of {Y}.`

**Метрики калибровки** (для каждого шаблона `T`, по уровням):
1. `Q_T(level)` — доля массы на candidate-set + purity (не служебные/формат токены).
   Требование: разброс `Q_T` по уровням мал (level-invariance прибора).
2. `MI_T` — взаимная информация «вставленное понятие ↔ выходное распределение».
   Требование: `MI_T` высоко (content-tracking; отличает от 009).
3. **Nonce-flatness** — подстановка бессмысленных слов: структура (потомки/уровень) ≈ 0.
4. **Frame-robustness** — согласие знака/уровня между шаблонами одного канала.

**Гейт:** шаблон допускается к основному прогону, если `Q`-разброс ≤ порога (фиксируется),
`MI_T` > нуля (перестановки), nonce-flat, и он согласован с ≥1 другим шаблоном канала.
Гипотеза **H_tmpl** (из промпт-опыта): более абстрактные шаблоны лучше по обеим осям
(`Q`-разброс вниз, `MI` вверх); проверяется этой же калибровкой.

## 6. Каналы и модели

- **Канал G** (генерация): чтение распределения по candidate-set в слоте шаблона; метрики §2
  (subtree-validity, level-step, монотонность).
- **Канал E** (entailment): `P(Yes)/(P(Yes)+P(No))`; AUC + градиент по дистанции.
- **Модели:** `Qwen2.5-1.5B-Instruct` (поведение, основной), `distilgpt2` (контроль/механика).
- Один и тот же вопрос — ≥2 шаблонами (readout-матрица, `PROGRAM.md` §4).

## 7. Сквозные контроли (`PROGRAM.md` §7)

1. **Факторный контроль candidate-set** (§4) — отделяет ветку от уровня от частоты.
2. **Частота+длина:** резидуализация; `margin = метрика − baseline`, baseline из Zipf-частоты
   и числа токенов, leave-one-out.
3. **Nonce-подстановка:** вся структура должна исчезать (синтаксический ноль).
4. **Перестановка меток таксономии** (random taxonomy): нуль для subtree-validity.
5. **Frame-robustness:** ≥2 шаблона; иначе — `readout-local`.
6. **Синтаксический baseline:** `Q` и «служебная масса» как отдельный baseline, а не надежда.
7. **Множественные сравнения:** перебор по шаблонам/классам — поправка; пороги — до прогона.
